# CodeInjector

[English](README.md) | **Русский**

Классический **x64 DLL-инжектор** — чистый WinAPI, один файл, ноль внешних зависимостей.

![Platform](https://img.shields.io/badge/platform-Windows%20x64-blue)
![C++](https://img.shields.io/badge/C%2B%2B-17-blue)
![License](https://img.shields.io/badge/license-MIT-green)

Техника: `OpenProcess` → `VirtualAllocEx` → `WriteProcessMemory` → `CreateRemoteThread(LoadLibraryA)` → `GetExitCodeThread`.

## ⚠️ Дисклеймер

Проект **образовательный**: разобраться в WinAPI, загрузчике DLL и в том, как устроены отладчики, профайлеры и системы хуков.

Используйте только в **своих** процессах или там, где есть явное разрешение. Инструмент не предназначен для обхода античитов, EDR и других защит и не содержит ничего для этого. Внедрение в чужие приложения может нарушать их EULA и законодательство. Ответственность за использование — на вас.

## Как это работает

```
CodeInjector.exe                        target.exe (x64)
──────────────────                      ────────────────
OpenProcess(pid)             ─────────► хэндл с минимальными правами
VirtualAllocEx               ─────────► буфер под строку пути
WriteProcessMemory           ─────────► "C:\...\Inject.dll\0"
CreateRemoteThread           ─────────► LoadLibraryA(remoteBuf)
                                            └─► DllMain(DLL_PROCESS_ATTACH)
WaitForSingleObject (15 с)   ◄───────── код выхода потока = HMODULE
GetExitCodeThread            ─────────► 0 → провал, != 0 → загружена
VirtualFreeEx + CloseHandle  ─────────► очистка на всех ветках выхода
```

Адрес `LoadLibraryA` берётся из своего процесса: база `kernel32.dll` общая для процессов одной сессии, поэтому он валиден и в цели.

## Возможности

- 🔎 Поиск процесса **по имени** (регистронезависимо, Toolhelp32) или указание **PID**.
- 🧩 **Несколько экземпляров** — список с индексами и выбор нужного.
- ⚙️ **Конфиг** `CodeInjectcfg.cfg` с ключом `target=`; если его нет — интерактивный запрос.
- 🧹 **Дисциплина ресурсов** — все хэндлы и удалённая память освобождаются на любой ветке, включая ошибки и таймаут.
- 🩺 **Внятная диагностика** — подсказки про права администратора, битность, зависимости DLL, блокировку AV.
- 📦 **Один файл**, собирается MinGW-w64 или MSVC, тянет только `kernel32`.
- 🧪 **Демо-DLL в комплекте** (`Inject.cpp`) — показывает MessageBox при загрузке.

## Требования

| | |
|---|---|
| ОС | Windows x64 (рекомендуется 10/11) |
| Компилятор | C++17 — MinGW-w64 (тестировалось на GCC 16) или MSVC 2019+ |

## Быстрый старт

```bash
# 1) инжектор
g++ -std=c++17 -O2 -m64 -static -o CodeInjector.exe CodeInjector.cpp

# 2) демо-DLL (покажет "Inject successful" при загрузке)
g++ -std=c++17 -O2 -m64 -shared -static -o Inject.dll Inject.cpp -luser32

# 3) запустите цель (например notepad.exe), затем
CodeInjector.exe
```

Команды для MSVC и CMake, описание конфига и разбор ошибок → **[гайд](USAGE.ru.md)**.

## Раскладка файлов

DLL ищется **строго рядом с exe** и называется **строго `Inject.dll`**:

```
C:\Tools\CodeInjector\
├── CodeInjector.exe
├── Inject.dll            ← ваша DLL (x64!)
└── CodeInjectcfg.cfg     ← опционально
```

Сейчас читается только `target`. Нет конфига / пустое значение → программа спросит цель в консоли.

## Про `Inject.cpp` (это только пример)

Демо-DLL вызывает `MessageBoxA` **прямо в `DllMain`**. Это намеренно просто, но блокирует loader lock: удалённый поток не вернётся, пока вы не нажмёте **OK**.

- Нажали OK **в течение 15 секунд** → инжектор напечатает `SUCCESS`.
- Нажали позже (или не нажали) → `Remote thread timed out` / `FAILED`, **хотя DLL реально загрузилась**.

В реальных задачах никогда не блокируйтесь в `DllMain` — создавайте рабочий поток. Неблокирующий вариант демо есть в [гайде](USAGE.ru.md#9-своя-dll).

## Известные ограничения

- **Только x64**; x86 и WOW64-цели не поддерживаются, битность цели заранее не проверяется.
- **ANSI-путь** (`LoadLibraryA`, имена через `CP_ACP`) — держите путь к DLL в ASCII.
- **HMODULE в логе усечён до 32 бит** (`GetExitCodeThread` отдаёт `DWORD`); проверка на NULL при этом корректна.
- **Нет выгрузки** — DLL остаётся до завершения процесса-цели.
- Имя DLL и таймаут 15 с **захардкожены**.
- **Таймаут ≠ отмена** — загрузка может завершиться уже после того, как инжектор сдался.
- Не работает против protected/PPL-процессов, политики «только Microsoft-signed DLL» и целей под античитом/EDR.
- `SeDebugPrivilege` не включается.
